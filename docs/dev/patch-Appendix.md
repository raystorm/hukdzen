# **Appendix A — Patch‑Package Details**

This appendix documents:

- the purpose of each patch
- the exact files patched inside `node_modules`
- the reason the patch exists
- the domains/features that depend on it
- any risks or maintenance notes

Patches are stored in:

```
/patches/
```

They are generated by **patch-package** and applied automatically on install.

---

# **A.1 Patch Workflow (Authoritative)**

### **Never edit patch files directly.**
Patch files are diffs — not source code.

### **Correct workflow:**

1. Modify the real file inside `node_modules`
2. Run patch-package to generate/update the patch
3. Run the `try-again` script to clear caches and reapply patches

### **Why `try-again` is required**

Node and Vite aggressively cache:

- resolved module paths
- transpiled JS
- sourcemaps
- type definitions
- ESM/CJS resolution results

Simply restarting the dev server is **not enough**.

Your `try-again` script performs the only reliable sequence:

- delete `node_modules`
- reinstall dependencies
- re-apply all patches
- clear caches
- ensure patched modules are actually used

This is the **only** correct way to refresh patched dependencies.

# **A.2 Patch: `@aws-amplify/storage`**

### **Purpose**

Fixes issues in Amplify Storage’s S3 provider that affect:

- file upload behavior
- metadata handling
- error propagation
- type definitions
- sourcemap correctness

These fixes are required for:

- the FileUploader domain
- ingestion alignment
- consistent behavior between local and cloud uploads

### **Patched Files**

```
node_modules/@aws-amplify/storage/dist/esm/providers/s3/index.js
node_modules/@aws-amplify/storage/dist/esm/providers/s3/index.d.ts
node_modules/@aws-amplify/storage/src/providers/s3/index.ts
node_modules/@aws-amplify/storage/dist/esm/providers/s3/index.js.map
```

### **Why these files**

- `index.js` — runtime behavior
- `index.d.ts` — TypeScript definitions
- `index.ts` — source of truth for ESM builds
- `index.js.map` — sourcemap alignment for debugging

### **Domains depending on this patch**

- **FileUploader** (primary)
- **docs** (indirectly, via ingestion)
- **Translator** (indirectly, via upload flows)

### **Risks / Maintenance Notes**

- Amplify updates may break or overwrite the patch
- After upgrading Amplify, regenerate the patch
- Always run `try-again` after modifying or regenerating the patch

# **A.4 Patch Naming Convention**

Patch files follow the format:

```
<package-name>+<version>.patch
```

Example:

```
@aws-amplify+storage+6.4.1.patch
```

This ensures:

- patches are tied to specific versions
- accidental upgrades break loudly
- contributors can see exactly what changed

---

# **A.5 Contributor Notes**

### **Do not create patches for:**

- app code
- domain code
- components
- utils
- anything inside `src/`

### **Do create patches for:**

- upstream bugs
- missing type definitions
- incorrect sourcemaps
- incorrect ESM/CJS exports
- behavior mismatches between local and cloud

### **Always document the reason for the patch.**
Future contributors must understand why it exists.
